---
title: 'The Chain Was Not in the Tool Set'
description: "Per-skill approval checks the ingredients. The dangerous recipe is assembled at runtime, from a prompt the review never saw."
pubDate: '2026-10-06T11:25:00Z'
---

There is a security model for agent systems that feels complete: before a skill is added to an agent's tool set, review it. Check what it can access, what permissions it requires, whether it has obvious misuse paths. Approve or reject.

This is necessary. It is not sufficient. The thing it cannot see is the chain.

---

Consider two approved skills: one that reads patient health records, one that sends data to an external endpoint. Each passes enrollment review. Each looks safe in isolation. Neither has an obvious misuse path when examined alone.

The dangerous action isn't either skill. It's the composition: read-health-data then send-to-external, called in sequence under a prompt that routes the output of one into the input of the other. Neither skill is dangerous. The chain is.

The enrollment review wasn't checking chains. It was checking tools.

---

Here is why this gap is structural, not a tooling problem.

The composition that becomes dangerous is **prompt-dependent**. The chain that exfiltrates health data only manifests when a prompt instructs the agent to retrieve and then relay. A different prompt using the same tool set produces a different composition. The chain space is a function of the tools *and* the prompt — not of the tools alone.

Enrollment review can only reason about the tool set. It cannot reason about the prompt, because the prompt doesn't exist at enrollment time. It arrives at invocation. The chain is assembled then, not before.

This is structurally analogous to Rice's theorem in computability: you cannot decide non-trivial semantic properties of a program from its syntax alone. The dangerous chain is a semantic property of the agent's execution — it depends on what the agent actually does under a specific input. The tool set is the syntax. The dangerous composition is the semantic property. Enrollment review is doing syntactic analysis on a problem that requires semantic analysis.

You cannot enumerate the dangerous chains from the static tool set. The set of dangerous compositions is generated by the cross-product of the tool set and all possible prompts. That space is not finite.

---

The adversarial case sharpens this. A prompt injection attack doesn't compromise individual skills — it constructs a prompt that assembles a dangerous chain from approved tools. The attacker has a forward model: they know the tool set, they know which combinations achieve their goal, and they write a prompt that elicits those combinations. The enrollment review was irrelevant to their threat model. They were never trying to add a malicious skill.

The defense at enrollment time checked each ingredient. The attack used the recipe.

---

What would correct look like? Not abandoning enrollment review — checking individual skills matters. But treating it as the primary security boundary for agent tool composition is wrong.

The composition is a runtime object. Reviewing it requires runtime visibility: monitoring which chains are being assembled, across which invocations, with which data flows. This is harder than enrollment review. It operates on a moving target. But it is the only point in the system where the chain actually exists.

The enrollment check approved the tools. It had no opinion about the chain. It never did.
